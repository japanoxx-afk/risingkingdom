# 버전 관리와 자동 업데이트

`version.json`이 버전의 기준입니다. `Version`은 런처 정식 버전이며 `주.부.수정` 숫자 3개를 사용합니다. `PatchVersion`은 번역 패치 버전으로 별도로 관리합니다. 컴파일 시 Windows 파일 버전·어셈블리 버전·화면 표시를 같은 값으로 생성합니다.

런처는 실행할 때 `japanoxx-afk/risingkingdom`의 GitHub Releases 최신 정식 배포를 확인합니다. 초안과 사전 공개 버전은 설치하지 않습니다. SHA-256과 크기, ZIP 파일명, 포함 경로 3개, 번역 사전 구조, 실행 파일 버전을 검증하고 별도 버전 폴더에 저장합니다.

새 프로세스의 시작 확인을 받은 뒤 이전 창을 닫습니다. 시작 실패 시 해당 버전을 실패로 기록하고 이전 창을 유지합니다. 서버 접속 실패 시 이전에 시작이 확인된 상위 버전 캐시 또는 현재 버전으로 계속합니다. 기존 EXE를 덮어쓰지 않고 다운그레이드하지 않습니다. 정상적으로 창을 연 뒤 게임 플레이 중 발생하는 문제까지 자동 판정하는 기능은 아닙니다.

저장 위치는 `%LOCALAPPDATA%\RisingKingdomsKO`입니다.

- `settings.json`: 게임 설치 경로
- `versions/<버전>/`: 검증된 새 런처 및 번역 사전
- `packages/<패치버전>-<사전해시>/`: 게임 패치 생성 캐시
- `downloads/`: 다운로드 임시 파일
- `handoffs/`: 새 프로세스 시작 확인 파일

자동 업데이트는 런처와 번역 사전을 갱신합니다. 게임 폴더는 자동 변경하지 않습니다. 번역 패치를 갱신하려면 게임을 종료하고 기존 패치를 **원본 복원**한 뒤 새 런처에서 **한글패치 적용**을 실행합니다. 게임 폴더에 저장한 원본 백업은 런처 업데이트와 독립적으로 유지됩니다.

## 새 버전 배포

1. `version.json`의 `Version`을 높입니다. 번역이나 패치 형식도 바뀌면 `PatchVersion`도 높입니다.
2. `CHANGELOG.md`를 갱신합니다.
3. `./test.ps1`, `./test-update.ps1`을 실행합니다. 텍스트 변환을 바꾸었으면 설치본이 있는 개발 PC에서 `./test-text.ps1`도 실행합니다.
4. 커밋 후 버전과 같은 태그를 올립니다. 예: 버전이 `0.4.1`이면 `v0.4.1` 태그입니다.
5. GitHub Actions가 Windows에서 빌드·검사 후 ZIP과 `update.json`을 Releases에 공개합니다.

이미 공개한 태그와 배포 파일은 덮어쓰지 않습니다. 잘못된 버전은 수정 버전 번호를 높여 새로 배포합니다. GitHub Actions가 비활성화되었거나 권한이 부족하면 배포 작업 로그를 확인해야 합니다.

수동 패키징은 `./package-release.ps1 -OutputDirectory <새 폴더>`로 할 수 있습니다. ZIP에는 런처 EXE, 번역 사전, 버전 정보만 포함되며 게임 원본·생성된 게임 패치·맑은 고딕 파일을 넣지 않습니다.
