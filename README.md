# Rising Kingdoms 텍스트 한글패치 런처

화면에 표시되는 텍스트를 한국어로 바꾸는 Windows 런처입니다. 음성·영상·이미지는 번역 대상에서 제외합니다.

**현재 배포는 기계번역 초안입니다.** 메뉴·기술명 일부를 직접 보정했으며 실제 게임 화면에서의 줄바꿈·잘림·문맥은 아직 검수하지 않았습니다. 원본 게임에서 추출한 번역 표식에만 적용하며 텍스트 전체의 100% 번역을 보장하지 않습니다.

## 사용법

1. [최신 배포](https://github.com/japanoxx-afk/risingkingdom/releases/latest)의 ZIP을 풀고 `RisingKingdomsLauncher.exe`를 실행합니다. 소스에서 실행할 때는 `Launch.cmd`를 사용합니다. 별도 Python이나 API 키는 필요하지 않습니다.
2. 게임 경로를 확인합니다. 기본값: `C:\Program Files (x86)\Steam\steamapps\common\Rising Kingdoms`
3. **한글패치 적용**을 누릅니다. 설치본의 텍스트를 번역 사전과 대조해 패키지를 로컬로 생성하고, 원본을 백업한 뒤 적용합니다.
4. **게임 실행**으로 시작합니다. 파일 쓰기 권한이 부족하면 런처를 관리자 권한으로 실행합니다.
5. **원본 복원**으로 패치 이전 파일을 복구할 수 있습니다.

소스 빌드 실행 파일은 `build/RisingKingdomsLauncher.exe`입니다. v0.4.0부터 실행 시 GitHub의 최신 정식 배포를 자동 확인하며, 새 버전을 검증한 뒤 자동으로 전환합니다. 오프라인이나 업데이트 실패 시 기존 버전으로 계속합니다. 예전 `RisingKingdomsKO.exe`와 `RisingKingdomsKO-Text.exe`에는 이 기능이 없으므로 새 실행 파일을 사용하세요.

런처 버전과 번역 패치 버전은 화면에 각각 표시합니다. 게임 경로와 업데이트 캐시는 `%LOCALAPPDATA%\RisingKingdomsKO`에 저장합니다. 런처가 갱신되어도 게임 파일은 자동 변경하지 않습니다. 새 번역 적용은 **원본 복원 → 한글패치 적용** 순서로 실행합니다. [버전 관리·배포 절차](docs/releases.md)와 [변경 이력](CHANGELOG.md)을 참고하세요.

## 패치 범위

| 대상 | 번역 표식 출현 수 | 작업 |
| --- | ---: | --- |
| `Packs/data.pak` | 4,821 | 메뉴·설정·유닛·건물·기술·아이템·도움말 등의 텍스트 |
| `adventures`의 세 종족 캠페인 및 튜토리얼 4개 | 1,971 | 이름·대사·목표 등의 텍스트 |
| `Local/Fonts/*.apf` 6개 | 해당 없음 | 기존 글리프를 보존하고 번역문에 필요한 한글 글리프 추가 |

파일별 범위를 포함한 고유 번역 키는 4,422개입니다. 영어 원문 해시가 사전과 일치할 때만 바꿉니다. `%s1`, `#GetClassInt(...)#` 같은 변수·계산식과 `@A` 같은 단축키를 검증합니다. 명령 단축키는 한국어 이름 옆에 영문자로 표시합니다.

캠페인 HPFS는 텍스트 파일에 새 블록을 할당하고 기존 파일 노드만 갱신합니다. 번역 대상 밖의 내부 파일은 바이트 단위로 보존하는지 검증합니다. 사용하지 않게 된 기존 텍스트 블록은 재활용하지 않으므로 패치본 크기가 늘어납니다.

`Local/english.pak`의 영어 음성 297개는 유지합니다. EXE에 내장된 오류 메시지, 번역 표식이 없는 문구, 이미지 속 영문, 사용자가 만든 맵은 현재 범위에 포함되지 않습니다.

## 번역과 글꼴

- `translations/ko.json`에는 번역 키·영문 해시·한국어 번역만 저장합니다. 원본 게임 파일은 저장소에 넣지 않습니다.
- 초안 작성 시 게임의 공개 영어 문구를 Google Translate 공개 엔드포인트로 번역했습니다. 런처는 네트워크 요청 없이 포함된 사전을 사용합니다.
- `tools/translate_catalog.py`는 개발용 재생성 도구입니다. 공개 엔드포인트의 가용성이 보장되지 않으며 사용자 문서·저장 파일·인증정보를 입력하면 안 됩니다.
- 한글 글리프는 사용자의 Windows에 설치된 맑은 고딕에서 로컬로 생성합니다. APF의 문자 범위·크기·8단계 알파 RLE를 검사합니다. 기존 영문·숫자 글리프와 자간 데이터는 보존합니다.
- `FontFormatVerified`는 파일 구조 검증을 뜻합니다. `RuntimeVerified`는 현재 `false`이며 실제 게임 렌더링 검수와 구분합니다.

## 백업·복구

모든 원본과 패치의 SHA-256을 검증하고, 모든 백업을 마친 뒤 파일별 원자적 교체를 시작합니다. 기록은 게임 폴더의 `.risingkingdom-ko`에 저장합니다. 작업 중단 후에는 **원본 복원**을 실행하세요. 외부 업데이트로 예상과 다른 파일이 있으면 덮어쓰기를 중단합니다. 복원 후 백업은 `.risingkingdom-ko-backup-*`에 남습니다.

기존 적용 기록이 있으면 재적용을 막습니다. 생성 패키지에 실패가 발생하면 `.building-*` 폴더에 남기고 최종 패키지로 인식하지 않습니다. 기존 패키지의 버전이 맞지 않으면 새 패키지 폴더를 선택하세요.

## 검증

```powershell
./test.ps1
./test-update.ps1
./test-text.ps1
```

`test.ps1`: 임시 데이터로 설치·복원·중단 복구·경로 이탈·손상 패키지·외부 변경 보존을 검사합니다.

`test-text.ps1`: 실제 설치본을 테스트 폴더로 복사한 뒤 PAK·캠페인·글꼴 패키지를 생성하고 11개 파일을 적용·복원합니다. 원본 설치본을 변경하지 않았는지도 SHA-256으로 확인합니다. 실제 게임 실행이나 캠페인 플레이 검증은 포함하지 않습니다.

개발용 독립 검증 도구 `tools/verify_text_package.py`는 내부 비텍스트 데이터 보존, 번역 ID 보존, UTF-8, 파싱 가능한 XML의 유효성, 기존 APF 문자 범위 보존을 확인합니다.

패키지 구조: [docs/package-format.md](docs/package-format.md).
